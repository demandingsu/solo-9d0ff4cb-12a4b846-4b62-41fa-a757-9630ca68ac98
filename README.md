# 访谈语料训练分发平台

面向访谈资料员的本地网页应用（FastAPI + SQLite + Docker Compose）。资料员上传已获授权的访谈文本，
按批次在后台生成训练用 CSV，查看状态并下载；当受访者撤回授权时，其语料立即停止分发；
还可以按批次检索提到同一政策术语的访谈原话，供人工质检。

## 启动

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>。

数据（SQLite 与导出文件）保存在命名卷 `portal-data`，`docker compose restart` / `up` 会复用，
因此撤回状态、待清理记录都会跨重启生效。要彻底重来：`docker compose down -v`。

本地直接运行（需要 Python 3.11+）：

```bash
pip install -r requirements.txt
uvicorn training_portal.main:app --port 8000
```

## 页面能做的事

1. **上传 CSV**：包含 `batch`（访谈批次）、`respondent_id`（受访者编号）、`text`（文本）三列；
   也接受中文表头「访谈批次 / 受访者编号 / 文本」。编码支持 UTF-8 与 GB18030。
2. **生成训练 CSV**：从下拉框选择批次，后台线程按 20 行一个分块写出临时文件，完成后发布为可下载文件。
3. **查看状态**：任务（排队 / 生成中 / 演示暂停 / 已完成 / 已阻止 / 失败）与导出文件
   （可下载 / 待清理 / 已删除）都有实时状态，页面会就地刷新行内容而不整页重载。
4. **撤回授权**：输入受访者编号，立即删除其全部语料行、锁定并清理所有含其文本的导出文件。
5. **下载**：仅 `ready` 状态可下载，且每次下载都现场复核授权。
6. **政策术语原话检索**：输入至少 3 个字符的连续词句，可限定批次，返回匹配原文（高亮命中处）、
   受访者编号与批次；也可通过 `/api/search?q=...&batch=...` 脚本化调用。

`/api/status` 提供同样的状态 JSON（含检索索引状态 `search`），便于脚本化演示。

## 检索索引（SQLite FTS5）

检索基于一个 **FTS5 外部内容表** `utterance_fts`，对 `utterances` 建立全文索引：

- **trigram 分词器**：把文本切成连续三字符组，因此中文、英文都能按「至少 3 个字符的连续词句」
  做子串匹配。默认的 unicode61 分词器会把整段中文当成一个词元，无法命中短语，故不适用。
- **触发器同步**：`utterances` 的 INSERT / DELETE / UPDATE 触发器在**同一个 SQLite 事务**里
  同步索引。所以新上传提交后立即检索得到，撤回删除的原文立即不再出现——不存在中间态。
- **整库重建是单事务**：`'rebuild'` 与状态翻转一起提交，失败则整体回滚到上一个好索引；
  状态写入 `search_index_state`（`building` / `ready` / `failed`）。
- **构建失败时检索不可用**：只有 `ready` 状态才会执行查询；`failed` 时页面与 `/api/search`
  （HTTP 503）都明确提示「检索不可用」，绝不借用不完整索引返回结果。上传、生成、撤回等
  其余功能不受影响。
- **重启可恢复**：启动时若 FTS 组件缺失会尝试创建；索引处于 `failed` 或与语料不一致
  （完整性检查 + 行数核对 + 命中探针）时自动重建，成功后检索恢复。页面也提供「重建检索索引」按钮。
- 检索词被包成 FTS5 短语并转义双引号，用户输入无法注入 `OR` / `NEAR` / 前缀等 FTS 运算符；
  高亮输出经 HTML 转义。

可用环境变量 `PORTAL_FAIL_INDEX_BUILD=1` 让下一次索引构建失败，用于演示「检索不可用 →
重启/重建恢复」；不设置时构建正常。

## 撤回的关键语义

| 场景 | 行为 |
| --- | --- |
| 撤回已生成的导出文件 | 立即置为 `pending_delete`，后台删除；删除前不可下载 |
| 撤回时该批次正在生成 | 下一个分块检测到撤回即中止整个任务，结果不发布（其文本与其他语料交错，只删其行仍会泄漏） |
| 撤回时任务停在「演示暂停」 | 任务被标记 `blocked`，发布闸门拒绝发布，临时文件删除 |
| 撤回后重新上传同号 | 上传时按编号过滤，计入「跳过撤回」，不会重新纳入 |
| 撤回后原文换了编号再传 | 撤回时记录文本 SHA-256，同文换号同样被拒 |
| 下载时发现已撤回 | 拒绝下载（HTTP 410），文件转入 `pending_delete` 并清理 |
| 删除失败 | 记录保持 `pending_delete`（含尝试次数与错误），永不可下载；后台与启动时持续重试 |
| 崩溃/重启 | 启动时删除残留临时文件与无主导出文件；中断的 `running`/`paused` 任务标记失败；`pending_delete` 继续清理 |

撤回记录、语料删除、导出锁定与任务中止在**同一个 SQLite 写事务**中提交，所有读取路径
（上传、生成、发布、下载）都在事务内读撤回表，因此不存在「已撤回但仍可导出/下载」的中间态。

## 演示开关

页面「演示设置」面板，或环境变量（首次启动写入 SQLite）：

| 开关 | 环境变量 | 默认 | 作用 |
| --- | --- | --- | --- |
| 生成暂停 | `PORTAL_PAUSE_GENERATION=1` | 关 | 文件写好但停在发布前（状态「演示暂停」），在这段窗口里撤回即可看到任务被阻止、文件不发布。再次关闭开关或最多 5 分钟后继续。 |
| 删除失败次数 | `PORTAL_DELETE_FAILURES=3` | 0 | 接下来 N 次删除尝试模拟失败，文件停留「待清理」；耗尽后自动删除成功，可演示「待清理 → 清理完成」。 |
| 删除持续失败 | `PORTAL_DELETE_ALWAYS_FAIL=1` | 关 | 删除一直失败，用于演示重启后继续清理且文件始终不可下载。 |

开关保存在 SQLite 中，重启后仍生效——这正是「重启后继续清理、不重新开放残留文件」的演示条件。
页面上的「立即重试清理」会清空失败次数预算并立即重试。

## 推荐的演示流程

```
docker compose up --build            # 打开 http://localhost:8000
1. 载入样例 batch_2026_spring.csv
2. 选择 2026-春季-01，后台生成 → 下载
3. 检索「智能手机」→ 命中 R-2001 的原话（含批次与高亮）；限定批次 2026-春季-01 则无命中
4. 撤回 R-1001 → 该导出立即变为不可下载并转为「已删除」；再检索其原文已查不到
5. 载入样例 reupload_revoked.csv → R-1001 与其原文（改用 R-9001）都被跳过，检索同样查不到
6. 勾选「生成暂停」→ 生成 2026-春季-02 → 状态「演示暂停」时撤回 R-2001 → 任务「已阻止」，无导出
7. 「删除失败次数」填 3 → 撤回导出中的任一编号 → 导出「待清理」→ 重启容器 → 仍不可下载，预算耗尽后自动删除
```

检索失败/恢复演示：设置 `PORTAL_FAIL_INDEX_BUILD=1` 后重启，页面显示「检索不可用」且
`/api/search` 返回 503；取消该变量再重启（或点「重建检索索引」），检索恢复且期间上传的语料全部可查。

样例：`samples/batch_2026_spring.csv`（两个批次）、`samples/batch_2026_summer.csv`、
`samples/reupload_revoked.csv`（撤回后重传同号 + 原文换号）。

## 代码结构

```
training_portal/
  main.py       FastAPI 路由、页面渲染、下载流、检索页与 /api/search
  service.py    CSV 解析、生成/撤回/发布/下载/清理、FTS5 索引生命周期与短语检索
  db.py         SQLite schema（WAL + BEGIN IMMEDIATE 单写者，含 FTS5 外部内容表与触发器）
  templates/    单一仪表盘页面（含检索卡片）
  static/       样式与就地刷新的轮询脚本
tests/          test_portal.py（20 个）+ test_search.py（21 个），覆盖上传、生成、各类撤回
                时序、删除失败、重启续清、文本换号，以及检索语义、索引失败/恢复、漂移自检
samples/        可直接上传的本地样例
```
